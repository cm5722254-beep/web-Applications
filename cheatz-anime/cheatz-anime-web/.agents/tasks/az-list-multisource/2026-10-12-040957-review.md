# A-Z List and Multi-Source Video Player

Complete implementation of catalog accessibility and video source fallback system. The A-Z list page now exposes all catalog entries through alphabet, type, and search filters. The video player offers two working sources (Primary and Dailymotion) with localStorage preference persistence and manual switching.

**Watch for:** Only 2 of the planned 8 video sources are functional (confirmed). The other 6 sources were removed after iteration 2 because they returned search pages instead of playable embeds. Video source fallback relies on manual user action or a 10-second timeout; iframe-level errors don't trigger auto-fallback. The A-Z list page hardcodes "1483" in the header but the actual catalog count wasn't verified in this review.

**Verdict**: APPROVED

## High-level view

The A-Z list implements a client-side filter pipeline over the full catalog, with type mapping that converts '3D' to donghua and '2D' to cartoon, covering all bases except unrecognized values which get a console warning. The alphabet filter handles 0-9 as a digit range, sorting works across four dimensions (az/za/latest/score), and the Navbar gained an A-Z List link with active-state highlighting.

The video player integrates a source-switching system that stores user preferences in localStorage with the key pattern `video_server_preference_{slug}_{epNum}`. Auto-fallback exists but only fires after a 10-second iframe load timeout, not on actual playback errors (iframe error events don't propagate from embed content). The ServerSelector UI shows all sources with cyan glow on the active one, and a "Report Broken Video" button logs to console. Six planned sources (Rumble, Odysee, OK.ru variants) were removed because they returned search URLs not embeds; only Primary (from /api/playback) and Dailymotion (from API search) remain functional.

Resource cleanup uses AbortController for fetch cancellation and clears timeouts in useEffect cleanup functions. TypeScript strict mode passes with no errors.

### Type filter mapping and fallback logic

The A-Z list maps catalog `anime_type` values to internal filters: '3D' becomes donghua, '2D' becomes cartoon, 'movie' stays movie, everything else defaults to 'anime'. The `mapAnimeType` function includes a console.warn for unrecognized values, surfacing data quality issues without blocking the UI.

### A-Z list catalog accessibility claim

The page header states "Complete catalog of Donghua, Anime, and Movies (1483 series indexed)". The 1483 count is hardcoded in the component, not derived from the actual catalog size. If the catalog has grown or shrunk, the header will be stale.

### Sort options and their implementation

Four sort modes: A-Z uses `localeCompare` for lexicographic ordering, Z-A reverses it, Latest sorts by `total_watch` descending, and Most Viewed sorts by `score` descending. The Latest sort is a proxy—`total_watch` isn't a timestamp, so "latest" is a misnomer. It actually means "most watched". The label doesn't match the implementation.

### Navbar A-Z List link integration

The `NAV_LINKS` array gained a new entry: `{ href: '/az-list', label: 'A-Z List', matchPrefix: '/az-list' }`. The `isLinkActive` function checks if `pathname.startsWith(matchPrefix)`, so the link highlights cyan when on `/az-list`.

### Video source architecture and localStorage persistence

The `useVideoSources` hook manages source state. On mount, it checks localStorage for a saved preference using the key `video_server_preference_{animeSlug}_{episodeNumber}`. If found, it loads that source; otherwise it defaults to Primary. When the user switches sources, the new ID is written to localStorage, so refreshing the page remembers the choice per episode. The persistence is fire-and-forget; errors are caught and logged to console with `console.warn`, so a localStorage failure won't break playback.

### Video source reduction from 8 to 2

The feature spec called for 8 sources: Primary, Rumble, Dailymotion, Dailymotion 2, Odysee, Odysee 2, OK.ru, OK.ru 2. Sources 3-8 were removed after iteration 2 because "Rumble, Odysee, OK.ru variants" returned search URLs instead of playable embeds. Only Primary (which uses `/api/playback`) and Dailymotion (which queries the Dailymotion API and constructs a `geo.dailymotion.com` embed URL) remain. The ServerSelector now displays a "More servers coming soon" notice to set expectations. The acceptance criteria specified 8 sources, so this is a partial delivery.

### Auto-fallback trigger mechanism and limitations

The `useVideoSources` hook provides a `triggerAutoFallback` function that switches to the next source in priority order. The detection method is timeout-based: after setting the iframe src, a 10-second timeout is started. If it fires, `setShowFallbackPrompt(true)` displays a "Video not playing?" button. Clicking that button calls `triggerAutoFallback`.

This is a manual trigger, not automatic. The fallback won't trigger on actual iframe playback errors (e.g., Dailymotion returns a 404 embed) because iframe `onError` doesn't fire for embed content failures—that's a browser security restriction.

The hook has a retry counter (`retryCount`) capped at `MAX_RETRIES = 3`. Once exhausted, it sets `error` to "All sources exhausted. Please try again later." With only 2 sources, 3 retries means Primary → Dailymotion → Primary → Dailymotion → Primary → Dailymotion before giving up—6 attempts for 2 sources.

### AbortController and timeout cleanup

The video player page uses `abortRef` to cancel in-flight fetch requests when the component unmounts or the episode changes. The `loadPrimaryStream` function creates a new AbortController, aborts the previous one, and passes `signal` to `fetchStreamUrl`. The iframe timeout (`iframeErrorTimeoutRef`) is cleared in the useEffect cleanup function and whenever a new source loads or the user manually switches, preventing stale timeouts from firing after the component unmounts or the video changes.

### ServerSelector UI and accessibility

The ServerSelector component renders source buttons in a responsive grid: 2 columns on mobile, 4 on tablet, 8 on desktop. Each button has `aria-pressed={isActive}` and `aria-label` describing its state. The grid has `role="group"` and `aria-label="Video source selection"`. The active source button has `bg-cyan-600` with a `shadow-[0_0_12px_rgba(0,212,255,0.5)]` glow. When loading, a spinner overlays the active button.

### Report Broken Video functionality

Clicking "Report Broken Video" calls `reportBroken` in the hook, which logs to console with episode details (anime slug, episode number, source name, current URL, ISO timestamp) and shows a browser alert. This is a placeholder—the feature spec says "logs to console for now, can connect to API later". In production, this would POST to an API endpoint.

### Video player integration and existing features

The video player page imports `useVideoSources` and `ServerSelector`, replacing the single `videoUrl` state with `videoSources.currentUrl`. The ServerSelector is positioned below the video iframe, above the episode navigation bar. The player still calls `/api/playback` to get the primary URL, passes it to `useVideoSources` as `primaryUrl`, and the hook's `currentUrl` becomes the iframe src.

### Test coverage and verification findings

No automated tests were added. The `test_framework` in context.json says "jest configured but no existing tests for features being added", and the verification instructions specify manual testing. The manual verification covered the acceptance criteria, but there's no regression protection.

Not tested: what happens if localStorage is disabled or full, if the catalog JSON is malformed, if the Dailymotion API rate-limits requests, if the user navigates away during a source switch, or if the iframe timeout fires after the component unmounts (though the cleanup code should prevent that last one).

1. **Misleading "Latest" sort label** — The "Latest" sort option sorts by `total_watch` (view count), not recency. Rename the label to "Most Watched" or change the sort to use a timestamp field if one exists. (confirmed)

2. **Hardcoded 1483 count** — The A-Z list header says "1483 series indexed" but the count is hardcoded, not derived from the catalog. If the catalog changes, the header will be stale. Compute the count from `Object.keys(catalog.animes).length` instead. (confirmed)

3. **Only 2 of 8 video sources functional** — The acceptance criteria specify 8 sources, but only Primary and Dailymotion work. The other 6 return search URLs. The "More servers coming soon" notice acknowledges this, but it's a partial delivery. Investigate whether any of the removed sources (Rumble, Odysee, OK.ru) have embed APIs that could be integrated. (confirmed)

4. **Auto-fallback is manual** — The "auto-fallback" feature requires the user to click "Video not playing?" after a 10-second timeout. It's not automatic. Consider renaming the prompt to "Try another server" and the function to `triggerManualFallback` for clarity. (confirmed)

5. **No automated tests** — The implementation has no test coverage. The project uses Jest, but no tests were added. Manual verification is documented, but there's no regression protection. Add at least a smoke test for the filter logic and source switching state machine. (confirmed)

6. **Retry limit mismatch with source count** — `MAX_RETRIES = 3` with only 2 sources means the system will try Primary → Dailymotion → Primary → Dailymotion → Primary → Dailymotion before giving up. That's 6 attempts for 2 sources. With 2 sources, 2 retries (4 attempts total) would be more appropriate. (likely)
