# A-Z List and Multi-Source Video System

The implementation adds comprehensive anime catalog browsing with 1483 entries accessible through filters and sorting, plus an 8-source video fallback system with localStorage persistence and auto-retry. Both features integrate cleanly into the existing Next.js 14 app router architecture. The video source system handles iframe load failures through timeout detection and manual source switching, and the A-Z list provides type filters, alphabet navigation, and sort options matching the reference implementation.

**Watch for:** Type mapping defaults all unrecognized types to 'anime' (likely, see mapAnimeType function); video sources 3-8 return search URLs not playable embeds (confirmed); localStorage errors silently suppressed (confirmed); iframe timeout never clears on unmount (confirmed).

**Verdict**: CHANGES_REQUESTED

## High-level view

The A-Z list page loads all 1483 anime from the static catalog and filters them client-side by letter, type, and search query, with four sort modes. Type mapping converts catalog values ('3D', '2D', 'movie') to internal enums but defaults everything else to 'anime', which may misclassify entries with unexpected type values.

The multi-source video system provides 8 sources with priority-ordered fallback, but only sources 1-2 (Primary and Dailymotion API search) return playable embed URLs. Sources 3-8 (Rumble, Odysee, OK.ru variants) construct search page URLs that cannot play in an iframe, so fallback stops working after the first two sources fail.

The video player uses a 10-second timeout to detect iframe load failures, showing a "Video not playing?" prompt, but the timeout ref is not cleared when the component unmounts or when a new episode loads, potentially triggering stale prompts after navigation.

localStorage saves video source preferences per episode and loads them on mount, but both save and load wrap all errors in empty catch blocks, silently failing when localStorage is blocked or full.

## Issues (4)

1. **Incomplete video source fallback** — Sources 3-8 return search URLs not embeds. Replace search URLs with actual embed patterns or remove non-functional sources from the list.

2. **Type mapping catch-all** — mapAnimeType defaults unrecognized types to 'anime'. Add validation or logging to surface unexpected catalog type values before they get misclassified.

3. **Stale iframe timeout** — iframeErrorTimeoutRef timeout persists across episode changes and unmount. Clear it in the cleanup function and when loadPrimaryStream runs.

4. **Silent localStorage failures** — Empty catch blocks hide localStorage errors. Log failures to console so blocked storage is visible during debugging.

## Type mapping defaults unknown values to anime

The `mapAnimeType` function in `az-list/page.tsx` maps catalog `anime_type` to internal filter values:

```typescript
function mapAnimeType(catalogType: string): string {
  const type = (catalogType || '').toLowerCase()
  if (type === '3d') return 'donghua'
  if (type === '2d') return 'cartoon'
  if (type === 'movie') return 'movie'
  return 'anime' // Default to anime for everything else
}
```

Any catalog entry with an `anime_type` value other than '3D', '2D', or 'movie' gets classified as 'anime'. Typos, unexpected values, or new types ('OVA', 'special', 'short') will be lumped into 'anime' without visibility. Add a console warning for unrecognized values to surface this during catalog updates.

## Video sources 3-8 return search URLs not playable embeds

The `videoSourceFinder.ts` service defines 8 sources, but sources 3-8 construct search page URLs rather than embed URLs:

```typescript
{
  id: 'rumble',
  name: 'Rumble',
  priority: 3,
  getUrl: (baseUrl, animeSlug, epNum) => {
    const animeName = animeSlug.replace(/-/g, ' ')
    const searchQuery = encodeURIComponent(`${animeName} episode ${epNum}`)
    return `https://rumble.com/search/video?q=${searchQuery}`
  },
}
```

The same pattern applies to Odysee and OK.ru sources. These URLs load search results pages, not video players, so the iframe shows a search page instead of playing video. The auto-fallback system will try Primary → Dailymotion → Rumble (search page) → fail. After the first two sources, the system is broken.

Possible fixes: remove sources 3-8 until proper embed URLs are available; implement server-side scraping to extract embed URLs from search results (high complexity); or document that only Primary and Dailymotion are functional and the rest are placeholders for future implementation.

## Iframe timeout never clears on unmount or episode change

The video player sets a 10-second timeout to detect iframe load failures:

```typescript
iframeErrorTimeoutRef.current = setTimeout(() => {
  setShowFallbackPrompt(true)
}, 10000)
```

The timeout is created in `loadPrimaryStream` but is only cleared at the start of that function if it's being called again. If the user navigates away from the episode page or switches episodes within 10 seconds, the timeout fires after the component unmounts or after a new episode has started loading, causing a React state update on an unmounted component or showing a stale prompt.

The `useEffect` cleanup function clears `intervalRef` and `abortRef` but not `iframeErrorTimeoutRef`:

```typescript
return () => {
  abortRef.current?.abort()
  if (intervalRef.current) clearInterval(intervalRef.current)
  if (iframeErrorTimeoutRef.current) clearTimeout(iframeErrorTimeoutRef.current)  // ← missing
}
```

Add `clearTimeout(iframeErrorTimeoutRef.current)` to the cleanup return and also clear it at the top of `loadPrimaryStream` before setting a new timeout.

## localStorage operations silently suppress all errors

Both `useVideoSources.ts` and the video player page wrap localStorage access in empty catch blocks:

```typescript
if (typeof window !== 'undefined') {
  try {
    localStorage.setItem(storageKey, source.id)
  } catch {
    // localStorage might be full or blocked
  }
}
```

The comment explains *why* errors might occur, but suppressing them entirely makes debugging difficult. Users will see their source preference reset on every page load with no console indication why. Change empty catch blocks to `catch (err) { console.warn('Failed to save video source preference:', err) }` so the failure is visible during development.
