# Video Health Check & Auto-Repair System

This change adds a video health monitoring and auto-repair system to the admin dashboard. It scans all episodes across the entire catalog, detects broken playback URLs via HEAD requests, and attempts automatic repair by querying alternative video sources. Admins can trigger full-catalog scans, batch auto-repair broken videos, or manually update individual episode URLs.

**Watch for:** (1) Server-side store is ephemeral — scan results vanish on server restart (confirmed). (2) No auth check in video API routes (confirmed) — anyone who can reach these endpoints can scan the catalog and write episode URLs. (3) Scan algorithm fetches episode lists sequentially per anime instead of using the backend's full episode list, causing O(anime_count) API calls (confirmed).

**Verdict:** NEEDS_CHANGES

---

## High-level view

The health check service maintains an in-memory Map of episode health records (episodeId → VideoHealthEntry) and exposes functions to scan, check URLs, and retrieve stats. URL health is determined by a HEAD fetch with 5-second timeout; 2xx/3xx responses pass, timeouts and errors fail. The scan fetches all anime paginated (50 per page), then fetches episodes per anime, then HEAD-checks each playback_url with 200ms rate-limiting between checks. Progress is tracked as `(checked / total) * 100`.

The auto-repair flow queries the internal `/playback` endpoint first, then falls back to an external animekill.com API, and writes the first working URL back to the backend via PUT `/admin/episodes/:id`. The fix and update routes call `apiClient.put`, which attaches the auth token from localStorage when running client-side but has no token in server-side Next.js route handlers, so those PUTs will fail with 401 unless the backend accepts unauthenticated admin writes.

Five API routes expose the system: `/api/admin/videos/scan` (POST starts background scan, GET returns stats+entries), `/api/admin/videos/check` (POST checks a single URL), `/api/admin/videos/fix` (POST auto-repairs one episode), `/api/admin/videos/update` (POST validates and writes a manual URL), and `/api/admin/videos/status` (GET returns current stats+entries). None of these routes verify the caller is an admin; they rely on apiClient to relay the frontend auth token, but in server-side execution context (Next.js route handlers) there is no localStorage and no token, so backend calls will fail.

The UI (`/admin/videos/health`) displays stats cards (total, working, broken, fixed), a scan progress bar, filter tabs, and a table of episodes with inline auto-fix and manual URL update controls. The admin dashboard landing page includes a Video Health Monitor card linking to this page. Theme fidelity is maintained: bg-[#07080f] body, bg-[#0d0f1a] cards, border-cyan-500/20 accents, rounded-2xl corners, font-extrabold headings.

<details>
<summary>Issues (7)</summary>

1. **Ephemeral store loses all scan data on server restart** — videoHealthStore is a module-level Map, so every restart wipes the scan history. Persist to Redis, database, or filesystem, or at minimum document this as transient state.

2. **No auth check in video API routes** — routes accept any POST without verifying the caller is admin. Add admin role check or at minimum relay the Authorization header from the incoming request to apiClient calls.

3. **PUT requests from route handlers have no auth token** — apiClient reads token from localStorage, which doesn't exist in server-side context. Pass the Authorization header from the incoming request to apiClient, or use a service account token for server-side writes.

4. **Scan fetches episodes per-anime instead of bulk** — the scan loops over every anime and fetches `/admin/anime/:id/episodes` one by one (O(anime_count) calls). Use the backend's bulk episode list endpoint if available, or batch by 100 anime at a time.

5. **No rate-limit protection on external animekill.com API** — auto-repair queries `https://apis.animekill.com` with no retry backoff or rate-limit handling. Add exponential backoff and handle 429 responses.

6. **HEAD fetch may fail on URLs that require auth or disallow HEAD** — some CDNs or video hosts reject HEAD or require query-string tokens. Fallback to GET with Range: bytes=0-0 or accept that some working URLs will be flagged broken.

7. **No test coverage for core health check logic** — checkVideoUrl, scanAllEpisodes, findAlternativeSource, and the fix flow have no test files. Add unit tests for URL validation, integration tests for the scan pagination, and mock tests for the auto-repair flow.

## Server-side store is ephemeral

`videoHealthService.ts` exports a module-level `Map<number, VideoHealthEntry>` named `videoHealthStore`, and a mutable `videoHealthStats` object. Every scan writes into this Map, but it lives in the Node.js process heap. When the Next.js dev server restarts, or when the production container restarts, all scan data vanishes. Admins will see empty state and have to re-scan the entire catalog.

For a catalog of 1,386+ titles (likely 10,000+ episodes), a full scan takes hours. Losing that state on restart is unacceptable. Persist the Map to Redis (hash per episodeId), SQLite, or JSON file, or at minimum document in the UI that scan results are session-only.

## No auth verification in video API routes

The five routes under `/api/admin/videos/` (`scan`, `check`, `fix`, `update`, `status`) accept POST or GET requests without checking that the caller is an admin. The frontend enforces `isAdmin` via `useAuth`, but any client that can reach the Next.js server can POST to `/api/admin/videos/scan` and trigger a background scan, or POST to `/api/admin/videos/update` and overwrite episode URLs.

The backend API requires admin role for PUT `/admin/episodes/:id`, so unauthorized writes will fail with 401, but the scan itself is a DDoS vector: an attacker can trigger 10,000+ HEAD requests from your server to arbitrary URLs by posting crafted episode records.

Add role verification at the top of each route:

```typescript
const token = request.headers.get('Authorization')
if (!token) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })

// Verify token with backend /auth/me or decode JWT and check roles
```

Or pass the Authorization header to apiClient (see next issue).

## Backend calls from route handlers fail auth

The fix and update routes call `apiClient.put('/admin/episodes/:id', ...)`. `apiClient` is an axios instance that attaches the auth token from localStorage via a request interceptor:

```typescript
if (typeof window !== 'undefined') {
  const token = localStorage.getItem('auth_token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
}
```

In Next.js route handlers (server-side context), `window` is undefined and localStorage doesn't exist, so `token` is always null. The interceptor attaches no Authorization header, and the backend PUT rejects with 401. Auto-repair will always fail unless the backend accepts unauthenticated admin writes (which would be a security hole).

Two solutions:

1. **Relay the caller's token:** Extract `Authorization` from the incoming request and pass it to apiClient:

   ```typescript
   const authHeader = request.headers.get('Authorization')
   await apiClient.put(`/admin/episodes/${episodeId}`, 
     { playback_url: foundUrl },
     { headers: { Authorization: authHeader } }
   )
   ```

2. **Service account:** Store an admin service token in an env var and use it for server-side writes:

   ```typescript
   const serviceToken = process.env.ADMIN_SERVICE_TOKEN
   await apiClient.put(`/admin/episodes/${episodeId}`,
     { playback_url: foundUrl },
     { headers: { Authorization: `Bearer ${serviceToken}` } }
   )
   ```

Option 1 is simpler and ensures the write is attributable to the caller.

## Scan algorithm is O(anime_count) inefficient

`scanAllEpisodes` fetches all anime paginated (lines 67–87 in videoHealthService.ts):

```typescript
while (hasMoreAnime) {
  const animeResponse = await apiClient.get(`/admin/anime?page=${currentPage}&per_page=50`)
  allAnime.push(...animeData)
  ...
}
```

Then for each anime, it fetches episodes one by one (lines 91–95):

```typescript
for (const anime of allAnime) {
  const episodesResponse = await apiClient.get(`/admin/anime/${anime.id}/episodes`)
  ...
}
```

If the backend has 1,000 anime, this makes 1,000 GET requests to fetch episodes. The backend likely exposes a bulk `/admin/episodes?per_page=500` endpoint that returns all episodes across all anime. Use that to fetch episodes in 10–20 requests instead of 1,000.

If no bulk endpoint exists, batch the per-anime requests: fetch episodes for 50 anime in parallel using `Promise.allSettled`, wait 1 second, fetch the next 50. This reduces wall-clock time by 50x.

## External API has no rate-limit handling

`videoSourceFinder.ts` fetches `https://apis.animekill.com/api/v1/playback?anime=${animeSlug}&episode=${episodeNumber}` with a raw `fetch()` call (lines 23–40). If the external API rate-limits or returns 429, the code logs the error and returns null, marking the episode as unfixable. During batch auto-repair, this means 100 broken episodes will hammer animekill.com in 50 seconds (500ms * 100), likely triggering rate limits and causing false negatives.

Add exponential backoff:

```typescript
let retries = 0
while (retries < 3) {
  const response = await fetch(externalUrl)
  if (response.status === 429) {
    await sleep(2 ** retries * 1000) // 1s, 2s, 4s
    retries++
    continue
  }
  if (response.ok) { ... }
  break
}
```

## HEAD fetch may incorrectly flag working URLs as broken

`checkVideoUrl` sends a HEAD request with 5-second timeout. Some video CDNs (Cloudflare Stream, AWS CloudFront signed URLs) reject HEAD or require query-string signature tokens that expire. A URL that returns 403 on HEAD might return 200 on GET. The scan will mark it broken even though players can stream it.

Either:

- Fallback to `GET` with `Range: bytes=0-0` if HEAD fails (RFC 7233 allows partial content requests).
- Accept that some working URLs will be flagged and let admins manually verify.
- Add a "verify" button in the UI that attempts to load the URL in an iframe or video element to confirm playback.
